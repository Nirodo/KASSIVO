Wofür ist das?

KASSIVO kann nachsehen, ob es auf GitHub eine neuere Version gibt, das Update-Paket herunterladen und prüfen. Installiert wird es danach mit dem Skript update.bat im Projektordner. So müssen Sie neue Versionen nicht mehr von Hand zusammensuchen.

So geht's

Update-Prüfung einschalten

  1. Öffnen Sie Update (/settings/update). Sie erreichen die Seite auch über Einstellungen, Link „Update: nach neuer Version suchen“.
  2. Setzen Sie den Haken „Update-Prüfung erlauben“ und wählen Sie „Einstellung speichern“.

Nach Updates suchen und herunterladen

  1. Wählen Sie „Jetzt nach Updates suchen“. KASSIVO zeigt „Version … ist verfügbar.“ mit den Release-Notizen oder „Sie haben die aktuelle Version.“
  2. Wählen Sie „Update herunterladen“. KASSIVO lädt das Paket, prüft die SHA-256-Prüfsumme und den Inhalt und meldet „Update … ist heruntergeladen und geprüft.“

Update installieren

  1. Beenden Sie KASSIVO: Schließen Sie das Fenster von start.bat.
  2. Starten Sie update.bat im Projektordner per Doppelklick.
  3. Bestätigen Sie die Frage „Update auf … jetzt installieren? (j/n)“ mit j.
  4. Das Skript sichert die Datenbank, tauscht die Programmdateien aus und prüft, ob die neue Version startet. Am Ende steht „KASSIVO … ist installiert. Bitte jetzt start.bat starten.“
  5. Starten Sie start.bat.

Beispiele

Beispiel: Sie haben 1.3.0 installiert, auf GitHub gibt es 1.4.0. Nach „Jetzt nach Updates suchen“ steht „Version 1.4.0 ist verfügbar.“. Nach „Update herunterladen“ liegt das Paket kassivo-1.4.0.zip im Ordner updates neben der Datenbank. update.bat legt zuerst eine Sicherung kassivo-JJJJMMTT-HHMMSS.db im Ordner backups an und installiert dann 1.4.0.

Beispiel: Die neue Version startet nach dem Austausch nicht. Das Skript meldet „Update fehlgeschlagen“ mit dem Grund und „Der alte Stand wurde zurückgesetzt.“ Sie arbeiten mit der bisherigen Version weiter.

Gut zu wissen

  • Standardmäßig aus. Ohne den Haken baut KASSIVO keine Verbindung ins Internet auf. Auch eingeschaltet fragt es nur, wenn Sie „Jetzt nach Updates suchen“ oder „Update herunterladen“ wählen, nicht beim Start und nicht im Hintergrund.
  • Was gesendet wird. Nur eine Anfrage an api.github.com und github.com für das feste Projekt, ohne Anmeldung, ohne Token und ohne Daten aus KASSIVO. Die Verbindung ist verschlüsselt, das Zertifikat wird geprüft, nach 10 Sekunden ohne Antwort bricht KASSIVO ab. Ein Firmen-Proxy aus der Umgebungsvariable HTTPS_PROXY wird verwendet.
  • Prüfsumme. Stimmt die Prüfsumme nicht, meldet KASSIVO „Die Prüfsumme des Update-Pakets stimmt nicht. Es wurde nichts gespeichert.“ Das Paket darf höchstens 50 MB groß sein und wird vor dem Speichern auf gefährliche Dateinamen geprüft.
  • Ihre Daten bleiben. Die Datenbank wird nie überschrieben. Ausgetauscht werden nur die Programmdateien im Projektordner. Die virtuelle Umgebung .venv, ein Git-Ordner .git und eigene Dateien, die nicht im Paket stehen, bleiben unberührt. Der alte Programmstand bleibt im Ordner .update im Projektordner; den können Sie nach einem erfolgreichen Update löschen.
  • Datenbankformat. Braucht die neue Version ein neues Datenbankformat, stellt sie es beim ersten Start um und legt vorher noch einmal eine Sicherung an.
  • Kein Neustart von selbst. KASSIVO startet sich nie selbst neu und tauscht nichts aus, solange es läuft. Läuft es noch, meldet update.bat „KASSIVO läuft noch (Port 8000 ist belegt).“ und ändert nichts.
  • Neue Abhängigkeiten. Braucht eine neue Version zusätzliche Python-Pakete, ruft update.bat pip install -e . auf. Dafür muss PyPI erreichbar sein. Klappt das nicht, wird der alte Stand zurückgesetzt.
  • Protokoll. Jeder Schritt steht in update.log im Ordner updates neben der Datenbank, ohne Namen oder IBANs.

Achtung: Die Update-Funktion setzt eine Installation mit pip install -e . im Projektordner voraus (wie in Erste Schritte beschrieben). Bei einer anderen Installation bricht update.bat mit einem Hinweis ab. Wer den Projektordner mit Git verwaltet, sieht nach dem Update geänderte Dateien in git status, bis er selbst auf das neue Tag wechselt.

Tipp: Darf Ihr Rechner nicht ins Internet (Firmenregeln), lassen Sie die Update-Prüfung aus und aktualisieren Sie wie bisher von Hand.
