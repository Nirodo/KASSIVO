Wofür ist das?

Kontoumsätze kommen per Datei in KASSIVO. Auf der Seite Import (/import) laden Sie den Export aus dem Online-Banking hoch. KASSIVO liest die Datei nur, fragt kein Bankkonto ab und braucht keine Zugangsdaten.

Unterstützt ist genau ein Format: camt.052.001.08, im Online-Banking „XML CAMT V8, gebuchte Umsätze“. Andere Formate (CAMT V2, MT940, CSV) lehnt KASSIVO ab.

So geht's

  1. Legen Sie vorher den Prüfungsstart fest (Beiträge und Prüfungsstart). Fehlt er, zeigt die Importseite einen Hinweis.
  2. Erzeugen Sie im Online-Banking den Export „XML CAMT V8, gebuchte Umsätze“ für den gewünschten Zeitraum. Sie bekommen eine ZIP-Datei mit einer XML-Datei je Buchungstag oder eine einzelne XML-Datei.
  3. Öffnen Sie Import, wählen Sie bei „Datei (ZIP oder XML)“ die Datei und dann „Importieren“. Entpacken Sie die ZIP-Datei nicht. KASSIVO liest sie direkt.
  4. Lesen Sie die Ergebnisseite „Import abgeschlossen“ (siehe unten).
  5. Gehen Sie weiter zu „Unklare Buchungen ansehen“ und ordnen Sie zu (Zahlungen zuordnen).

Was nach dem Import automatisch passiert

  1. KASSIVO legt nur neue Buchungen an. Bereits bekannte erkennt es als Duplikate.
  2. Auf die neuen Buchungen wendet es die Kategorien-Regeln an (Kategorien und Regeln).
  3. Neue Zahlungseingänge ordnet es automatisch Mitgliedern zu, wenn die Absender-IBAN eindeutig bekannt ist, und berechnet die Verteilung auf Beitragsmonate.
  4. Die Ergebnisseite zählt auf: „Neu“, „Duplikate“, „Automatisch kategorisiert“, „Automatisch zugeordnet“ und die Zahl der Vorschläge zur Bestätigung (offene Vorschläge insgesamt, nicht nur aus diesem Import). Der Link dort führt zu den offenen Vorschlägen.

Beispiele

Beispiel: Sie importieren eine ZIP-Datei mit 30 Buchungen. Ergebnis: Neu 30, Duplikate 0. Eine Woche später exportieren Sie einen größeren Zeitraum, der die 30 Buchungen noch einmal enthält, und importieren erneut: Neu 12, Duplikate 30. Doppelt angelegt wird nichts.

Beispiel: Warnung: „Saldo stimmt nicht: Konto XX00…0001, 2026-03-05“. Die Datei für diesen Tag enthält einen Anfangssaldo, einen Schlusssaldo und Buchungen, die nicht zusammenpassen. Die Buchungen sind trotzdem importiert. Prüfen Sie im Online-Banking, ob der Export vollständig ist.

Gut zu wissen

Duplikate

  • KASSIVO erkennt Duplikate je Konto an der Bankreferenz der Buchung. Hat eine Buchung keine, bildet es einen Fingerabdruck aus Buchungsdatum, Betrag, Gegenpartei-IBAN und Zweck. Zwei sonst gleiche Buchungen in derselben Datei zählen dabei getrennt.
  • Ein mehrfacher Import derselben Datei ist deshalb sicher.

Grenzen

  • Eine hochgeladene Datei darf höchstens 100 MB groß sein.
  • In einer ZIP-Datei liest KASSIVO höchstens 5000 XML-Dateien. Jede XML-Datei darf höchstens 20 MB groß sein, alle zusammen höchstens 200 MB.
  • Eine Datei darf genau einen Bericht (ein Konto, einen Buchungstag) enthalten.

Alles oder nichts

Findet KASSIVO in irgendeiner Datei einen Fehler, bricht der ganze Import ab und legt nichts an. Die Meldung endet dann mit „Es wurde nichts importiert.“ Beheben Sie die Ursache und laden Sie die Datei erneut hoch. Das ist gefahrlos.

Bei einer Datei aus einer ZIP-Datei steht der Name der XML-Datei vor der Meldung, bei einer einzelnen XML-Datei upload.xml.

Weiteres

  • Nur gebuchte Umsätze: KASSIVO übernimmt Einträge mit dem Status „gebucht“ (BOOK) und überspringt alle anderen.
  • Sammelbuchungen (eine Buchung mit mehreren Einzelposten) importiert KASSIVO ohne Gegenpartei. Sie werden daher nie automatisch einem Mitglied zugeordnet und stehen, wenn es Eingänge sind, in „Unklar“.
  • Einträge mit 0,00 € machen den Import der ganzen Datei unmöglich („ungültiger Betrag“). Nur bei den Salden ist 0,00 erlaubt.
  • Echte Bankdateien gehören nie in Git, Issues oder Pull Requests.

Achtung: Beginnt der Export mitten im Monat, fehlen Zahlungen dieses Monats. Setzen Sie den Prüfungsstart auf den ersten vollen Monat des Exports.
