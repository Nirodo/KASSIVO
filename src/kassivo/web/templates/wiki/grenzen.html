Wofür ist das?

KASSIVO 1.0.0 ist bewusst klein gehalten. Diese Seite nennt offen, was es nicht kann, damit Sie nicht danach suchen.

So geht's

  1. Lesen Sie die Liste, bevor Sie KASSIVO für eine neue Aufgabe einsetzen.
  2. Planen Sie für Lücken einen Umweg ein, den die Hinweise nennen.

Einschränkungen

Bank und Import

  • Nur Dateiimport. KASSIVO liest nur Dateien im Format camt.052.001.08 („XML CAMT V8, gebuchte Umsätze“). Eine direkte Bankabfrage (FinTS, finAPI) gibt es noch nicht. Einen Adapter für C24 auch nicht.
  • Einträge mit 0,00 € brechen den Import der ganzen Datei ab („ungültiger Betrag“). Der Import ist alles oder nichts. Mehr als ein Bericht pro Datei geht ebenfalls nicht.
  • Duplikaterkennung mit Grenzen. Selten, aber möglich: Eine Buchung mit derselben Bankreferenz wie eine frühere, aber anderem Betrag oder Datum, wird still als Duplikat verworfen. Eine zweite gleiche Zahlung ohne Bankreferenz am selben Tag wird verworfen, wenn sie in einer späteren Datei kommt (die laufende Nummer beginnt je Datei neu). Beides sehen Sie nur an der Zahl „Duplikate“.
  • Import und Folgeschritte sind getrennt. KASSIVO speichert die Buchungen, bevor Regeln und automatische Zuordnung laufen. Scheitert einer dieser Schritte, bleiben die Buchungen ohne Kategorie und ohne Mitglied, und ein erneuter Import zählt sie als Duplikate. Abhilfe: „Regeln anwenden“ (Kategorien) und „Unklare automatisch zuordnen“.

Zuordnung und Daten

  • Gelernte IBANs lassen sich nicht wieder vergessen. Eine IBAN wird nur mehrdeutig, wenn sie einem zweiten Mitglied zugeordnet wird. Eine einmal mehrdeutig gewordene IBAN bleibt es: Sie wird nie für das richtige Mitglied neu gelernt und lässt sich nicht „vergessen“.
  • „— keins —“ ist nicht endgültig. Eine Zahlung, die Sie auf „Unklar“ zurücksetzen, ordnet KASSIVO über die gemerkte IBAN wieder zu, sobald Sie „Unklare automatisch zuordnen“ wählen oder bei einer anderen Zahlung derselben IBAN „Absender merken“ benutzen.
  • Zwei offene Vorschläge desselben Mitglieds können denselben Monat treffen. KASSIVO weist nur mit dem Hinweis „Monat bereits bezahlt“ darauf hin, sobald ein Monat durch bestätigte Zahlungen voll bezahlt ist.
  • Ein Austritt vor dem Eintritt wird akzeptiert. KASSIVO prüft die Reihenfolge der beiden Daten nicht. Achten Sie beim Eintragen selbst darauf.
  • Keine Längenbegrenzung bei den Textfeldern der Mitglieder (Name, Adresse, E-Mail, Telefon).
  • Kein Löschen: Buchungen, Mitglieder, Kategorien und Regeln lassen sich in der Oberfläche nicht löschen. Kategorien und Regeln lassen sich auch nicht ändern. Eintritt und „Zahlt ab Monat“ lassen sich nach dem Anlegen nicht mehr ändern. Korrekturen laufen über Zuordnung, Verteilung, Austritt und Mitgliedsart.
  • Eine Kasse je Datenbank. Mehrere Mandanten oder Vereine in einer Datenbank gibt es nicht. Für eine zweite Kasse nutzen Sie eine zweite Datenbank (KASSIVO_DB, siehe Erste Schritte).
  • Keine Buchungen von Hand: Buchungen entstehen nur durch den Import. Barzahlungen und eigene Ausgaben lassen sich nicht eintragen. Der Monat einer Barzahlung bleibt überfällig, und es gibt in 1.0.0 keine Abhilfe.
  • Beträge sind nur in Euro.

Auswertung

  • Prognose betrachtet nur Mitgliedsbeiträge. Wiederkehrende Ausgaben wie Miete oder Versicherung kennt sie nicht. Der Jahresbeitrag an den Hauptverein hat keinen festen Termin in KASSIVO. Er erscheint als Ausgabe, sobald er im Kontoexport steht.
  • Diagramme brauchen JavaScript im Browser. Die Tabellen im Report gehen immer.
  • Reports und Listen lassen sich nicht exportieren (kein CSV, kein PDF).

Betrieb

  • Ein Nutzer, ein PC, keine Anmeldung. Es gibt kein Login und keine Benutzerkonten, keine Rollen und keinen Mehrbenutzerbetrieb. Siehe Datenschutz und Sicherheit.
  • Kein Wiederherstellen-Knopf. Sicherungen erstellen Sie im Programm, zurückspielen müssen Sie von Hand (Sicherung und Wiederherstellung). Es gibt keine automatische Sicherung.
  • Port und Adresse sind fest: 127.0.0.1:8000.
  • Das Wiki ist nur zum Lesen. Es lässt sich im Programm nicht bearbeiten.
  • Python: Erlaubt ist Python ab 3.10. Getestet wird nur mit Python 3.15.
  • Sprache: Die Oberfläche ist nur auf Deutsch.

Beispiele

Beispiel: Eine Datei enthält eine Buchung mit 0,00 €, etwa eine Bankinformation. KASSIVO lehnt die ganze Datei ab und importiert nichts. Eine ZIP-Datei mit dieser Tagesdatei lässt sich dann gar nicht importieren. Lassen Sie den Tag nicht einfach aus dem Export weg: Alle Zahlungen dieses Tages fehlen dann für immer, weil es keine Buchung von Hand gibt, und die betroffenen Monate erscheinen überfällig, obwohl bezahlt wurde. Klären Sie den Tag mit der Bank (zum Beispiel ein erneuter Export ohne die 0,00-Buchung) oder nehmen Sie die Lücke hin, bis eine spätere Version solche Einträge mit einer Warnung überspringt. Melden Sie den Fall als Issue (ohne echte Bankdaten).

Gut zu wissen

Tipp: Fehlt Ihnen eine Funktion, legen Sie ein Issue im Projekt an (ohne echte Bankdaten).
